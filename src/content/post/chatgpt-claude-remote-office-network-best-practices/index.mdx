## 一、OpenAI 与 Claude 的底层风控机制剖析

生成式 AI 模型的 API 与 Web 交互依赖高强度的反作弊与合规审查。了解其背后的审查逻辑，是规避封号的关键。

```
┌────────────────────────────────────────────────────────┐
│             AI 服务商请求风控检测链路                    │
└────────────────────────────────────────────────────────┘
  用户向 ChatGPT / Claude 发起请求
       │
       ▼
  [ 第一道：Cloudflare CDN / WAF ]
       │ ── 检验 TLS 指纹 (JA3/JA4) 与浏览器特征
       │ ── 检验 IP 是否属于已知代理黑名单或机房 ASN
       ▼
  [ 第二道：第三方欺诈评分系统 (IPQS / MaxMind) ]
       │ ── 欺诈分 (Fraud Score) > 30 ➔ 强制弹出验证码
       │ ── 欺诈分 > 75 或机房标记 ➔ 直接返回 1020 拒绝访问
       ▼
  [ 第三道：平台业务风控 (OpenAI / Anthropic 风控引擎) ]
       │ ── 会话期间 IP 归属国频繁跳动 ➔ 锁定账号审查
       │ ── 单一 IP 存在几百个账号高频并发 ➔ 批量风控封停
       ▼
  成功进入对话界面 / 获取 Stream Token 输出
```

### 1. 致命缺陷：机房 IP（Hosting / Data Center）
很多低成本中转机场为了节省成本，采用 AWS、DigitalOcean、Linode 或各类廉价 VPS 作为落地节点。此类 IP 的 ASN 属性公开注册为 `Hosting` 或 `Data Center`。OpenAI 与 Claude 对此类 IP 极为敏感，几乎默认将此类流量划入高风险审查队列。

### 2. IP 欺诈评分（IP Fraud Score）
大型风控数据库（如 IPQualityScore、Scamalytics）会对全球 IP 进行实时信誉打分。若该 IP 近期存在垃圾邮件、撞库扫描或几千个设备共用一条出口，其评分就会飙升至 80~100。一旦使用此类 IP 访问 Claude，极易触发 `Your account has been disabled` 封禁提示。

### 3. 地理位置漂移与 WebRTC 泄漏
早上使用美国节点登录 Claude，下午为了看视频切换到日本节点，晚上又切到英国节点——这种跨大洲的瞬时物理移动会被风控引擎直接识别为「账号被盗」或「共享账号出租」，进而触发自动封控。

## 五、环境纯净度避坑清单

即便拥有了最优质的节点，若本地浏览器环境存在隐患，仍可能触发风控：
1. **启用独立的浏览器 Profile**：建议使用 Chrome 或 Edge 的多用户功能，为 AI 工具设立专用的工作 Profile，不与日常浏览混合。
2. **关闭浏览器 WebRTC 真实 IP 广播**：在浏览器安装 WebRTC Control 插件，禁止网页通过 WebRTC 探测并上报您的真实内网 IPv4/IPv6。
3. **保持节点固定**：为 ChatGPT 与 Claude 选定某一个优质节点后（如「美国 01」或「新加坡 01」），长期保持使用该节点，切勿频繁更换国家。
